# Beta Feedback Guide

このドキュメントは Mac プライベートベータ（初期ユーザー約10名）向けのフィードバックガイドです。

---

## フィードバックチャンネル

| 種別 | 送り先 |
| ---- | ------ |
| バグ報告・動作異常 | [GitHub Issues](https://github.com/ShinHaya/Catashiro/issues/new?template=beta-bug.md) |
| 改善提案・機能要望 | [GitHub Issues](https://github.com/ShinHaya/Catashiro/issues/new?template=beta-feedback.md) |
| インストール時の問題 | [GitHub Issues](https://github.com/ShinHaya/Catashiro/issues/new?template=beta-bug.md) — タイトルに「インストール:」を付けてください |

現時点では GitHub Issues を一元窓口とします。Issue を書くのが難しい場合はメンテナに直接連絡してください。

---

## 報告前に必ず確認してください

> **⚠️ 個人情報・パスワード・カード番号・API キーは絶対に記載しないでください。**

フィードバックに含めてよい情報:

- アプリのバージョン（設定画面または `About` に表示）
- macOS のバージョンと Mac の機種（例: macOS 15.3 / M2 MacBook Air）
- 操作手順の再現ステップ（フェイクデータや仮の URL で記載してください）
- エラーメッセージのスクリーンショット（個人情報が映らないようトリミング）
- リダクション済みサポートバンドル（取得方法は下記）

含めてはいけない情報:

- 本名・住所・電話番号・メールアドレスなど実際の個人情報
- サイトのパスワード・ログイン ID
- クレジットカード番号・CVV・有効期限
- AI プロバイダの API キー
- ボルトファイル（暗号化済みでも添付しない）

---

## サポートバンドルの取得方法

アプリのログや設定情報を安全に共有する場合は、自動でリダクション処理をするサポートバンドルを使用してください。個人情報の値は自動で除外されます。

1. アプリを開き「設定」タブに移動する
2. 「サポートバンドルを書き出す」ボタンをクリックする
3. 確認ダイアログで内容を確認し「書き出す」をクリックする
4. 生成された ZIP ファイルを Issue に添付する

サポートバンドルに含まれる情報:

- アプリのバージョン・OS バージョン・Node.js バージョン
- 暗号化スキーム・ストアフォーマットバージョン
- フィールド名一覧（値は含まない）
- サイト ID 一覧（URL やサービス名、登録値は含まない）
- 直近のアプリログ（個人情報の値はマスク済み）

## フィードバックテンプレート質問

GitHub Issues に報告する際は、以下の観点を参考にしてください。

### インストール・初回セットアップ

- インストール手順（ZIP 展開 → Gatekeeper 回避 → 初回起動）でつまずいた点はありましたか？
- ユーザーマニュアルの手順と実際の画面は一致していましたか？
- ボルト設定（パスフレーズ・リカバリキー）の説明は十分でしたか？

### 個人情報の管理

- プロフィール画面でのフィールド追加・編集はわかりやすかったですか？
- カード情報やパスワードの入力・マスク表示は期待通りでしたか？

### サイト追加（新規登録・既存アカウント取り込み）

- URL を入力してから登録完了までの流れは自然でしたか？
- フォームのフィールド検出はどのくらい正確でしたか？（誤ったフィールドへの入力はありましたか？）
- 確認ゲート（「このサイトに登録します。よろしいですか？」）の表示は分かりやすかったですか？
- 既存アカウントの取り込みはスムーズでしたか？

### 登録・更新の結果

- 登録は最後まで成功しましたか？失敗した場合はどのステップで止まりましたか？
- 一括更新（住所変更など）の精度と使い勝手はどうでしたか？

### CAPTCHA・二段階認証の引き継ぎ

- CAPTCHA や SMS/OTP が出た場合、引き継ぎ画面は表示されましたか？
- 手動で解決した後、アプリは自動的に再開しましたか？

### ユーザーマニュアル

- 読んでわかりにくかった箇所や、手順が足りなかった箇所はありましたか？

## メンテナがフィードバックを Issue に変換する手順

受け取ったフィードバックを実装 Issue に変換するときは以下を守ってください。

1. **個人情報を含まないこと**: 報告者の実データが Issue に載らないよう確認する。
2. **再現ステップをフェイクデータで書き直す**: 実際の URL やメールアドレスは使わない。
3. **重複確認**: 既存 Issue と重複していないか検索する。
4. **ラベルを付ける**: `bug` / `enhancement` / `documentation` / `beta-feedback` などを適切に設定する。
5. **実装計画テンプレートを使う**: 修正 Issue は `.github/ISSUE_TEMPLATE/implementation-plan.md` のフォーマットで作成する。
6. **スクリーンショットのトリミング**: 個人情報が映っている場合は記載しない（報告者に再提出を依頼する）。

## プライバシーポリシー（フィードバック収集）

- フィードバックは GitHub Issues 上でのみ管理します（外部フォーム・アナリティクスツールは使用しない）。
- 報告者が誤って個人情報を含めた場合、メンテナは速やかに Issue を非公開化または削除し、再報告を依頼します。
- サポートバンドル以外のログファイルやボルトファイルの添付は受け付けません。
